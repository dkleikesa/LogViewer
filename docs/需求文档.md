## 1. 产品定位

### 1.1 产品目标

提供一个面向**大规模文本、日志文件**的高性能分析工具，帮助用户快速完成：查看文本、搜索关键内容、按条件筛选、高亮不同类型的信息、标记重要行、在结果之间快速跳转、导出分析结果。

核心目标：

> **让用户从海量文本中快速找到自己真正关心的信息。**

### 1.2 核心价值

1. **大文件不卡顿**：上百 MB 的日志文件也能快速打开、流畅滚动；
2. **快速定位**：过滤器、查找、标记、命中跳转四种手段层层缩小范围；
3. **视觉区分**：不同过滤器配置不同前景色/背景色，让关键日志一眼可辨；
4. **配置可复用**：过滤器集合可保存、加载、分享，团队共用同一套分析规则。

### 1.3 差异化定位

参考 TextAnalysisTool 的**本地可执行、离线处理、聚焦大文本定位**的工具形态，本产品不止是跨平台文本查看器，而是服务于开发、测试和运维排障的工作台：

1. **跨端一致**：桌面优先，移动端可复用查询、过滤器、书签与分析会话；
2. **结构化渐进增强**：未知格式按原始文本安全呈现；识别到日志或 JSON 时补充字段与关联能力，不改变原始内容；
3. **排障闭环**：从发现异常、查看上下文、关联 Trace/Request ID，到导出可复现证据一体完成；
4. **本地与隐私优先**：文件、索引、会话与导出默认仅保存在设备本地；远程数据源作为后续受控扩展，不纳入 MVP。

### 1.4 产品核心模型

```text
Document（当前加载的完整文本）
      │
      ├── Lines（行，最小分析单位）
      ├── Filters（定义"哪些行值得关注"）
      │     ├── Include（包含）
      │     └── Exclude（排除）
      ├── Markers（用户手工标记的重要行）
      └── Search（临时搜索，不改变 Filter 状态）
              │
              ▼
        Filtered View（过滤后的视图）
```

## 2. 核心用户场景

### 2.1 日志分析

```text
INFO  Network connected
INFO  Request started
ERROR Connection timeout
INFO  Retry request
ERROR Connection timeout
```

用户希望：① 找出所有 ERROR → ② 高亮 ERROR → ③ 隐藏 INFO → ④ 在 ERROR 之间快速跳转 → ⑤ 查看某个 ERROR 前后的上下文。

### 2.2 多条件分析（"可视化日志"）

分析 Android Logcat 时，用户建立多个过滤器组合：

| Filter  | 条件                | 颜色 |
| ------- | ----------------- | -- |
| Crash   | `FATAL EXCEPTION` | 红色 |
| Error   | `ERROR`           | 黄色 |
| Network | `Network`         | 蓝色 |
| ANR     | `ANR`             | 紫色 |

最终形成一份一眼可读的"可视化日志"。

### 2.3 复杂文本搜索

普通字符串、大小写匹配、正则表达式（如 `Exception.*timeout`、`HTTP/[0-9.]+ [45][0-9]{2}`）定位复杂日志。

### 2.4 跨平台场景

| 场景      | 描述                                         |
| ------- | ------------------------------------------ |
| S1 桌面分析 | 开发/测试人员在 PC 上分析几百 MB 的 App 或服务端日志，配过滤器排查崩溃 |
| S2 移动现场 | 工程师在外用手机/平板打开从 IM、网盘导出的日志文件快速查看            |
| S3 团队共享 | 把调好的过滤器集合发给同事，对方加载后直接复用同样的高亮规则             |
| S4 现场抓取 | 通过系统分享（Android / iOS 分享面板）把日志文件直接送入 App    |

### 3.3 Filter 系统（核心功能）

#### 3.3.1 Filter 类型与匹配方式

| 编号   | 需求          | 说明                                                     | 优先级                   |
| ---- | ----------- | ------------------------------------------------------ | --------------------- |
| F3-1 | Include 过滤器 | 有任一启用 Include 时，命中任一条件的行进入候选集；**无启用 Include 时，全部行进入候选集** | P0                    |
| F3-2 | Exclude 过滤器 | 在候选集上执行，命中的行被隐藏；因此可在未配置 Include 时单独用于屏蔽噪声行               | P0                    |
| F3-3 | 匹配方式        | ① 文本包含（String）② 正则表达式（Regex）③ 按标记类型（Marker）；均支持大小写敏感开关 | P0（Marker 匹配随标记功能 P1） |

#### 3.3.2 Filter 属性模型

每个过滤器包含以下属性（新增/编辑对话框的字段依据）：

```text
Filter
├── Name            名称
├── Pattern         匹配内容（字符串或正则）
├── Type            Include / Exclude
├── Match Mode      String / Regex / Marker
├── Case Sensitive  大小写敏感
├── Foreground Color 前景色
├── Background Color 背景色
├── Enabled         启用状态
└── Description     描述（可选）
```

## 4. 非功能需求

### 4.1 大文件性能（P0 核心需求）

**数据读取原则：逻辑上完整加载，物理上按需缓存。**

- 文件读取一次后进入分析状态，此后：原文件变化/删除不影响当前分析；过滤与搜索不重复读盘；
- 同时不允许"全部文本常驻内存"作为唯一方案，超大文件需按需缓存（内存 + 文件索引配合）。

目标分档：

| 文件规模   | 体验目标                          |
| ------ | ----------------------------- |
| 100 MB | 流畅（核心场景）                      |
| 500 MB | 可用                            |
| 1 GB   | 可用                            |
| 5 GB+  | **支持**（已确认纳入目标；允许合理降级，如索引耗时增加、首次滚动需短暂等待，但打开、浏览、过滤、搜索核心功能必须可用） |

### 4.2 渲染与响应性能

- 过滤、搜索在后台执行，**不卡死、不阻塞 UI**，执行中可取消；
- 大量行滚动流畅（桌面 60fps、移动端 60fps 目标）；
- 大量过滤器同时启用不明显降低性能；
- 超长单行不会导致 UI 崩溃（配合 F2-4 截断显示）。

### 4.3 兼容性

| 平台      | 要求                                     |
| ------- | -------------------------------------- |
| 桌面      | macOS 12+ / Windows 10+ / 主流 Linux 发行版 |
| Android | 8.0+（minSdk 24）                        |
| iOS     | 15+                                    |
| Web     | P2 增强；以浏览器文件访问能力和大文件性能方案评估结果为准 |

### 4.4 隐私与数据安全

- 纯本地处理，无网络上报、无第三方统计 SDK，完全离线可用；
- 文件内容、建立的索引、最近文件和分析会话均不得在未获用户明确操作前离开设备；
- 复制、导出、分享前须展示范围与数量；启用脱敏规则时，预览结果应清楚区分原始文本与替换结果；
- 后续若接入远程日志源，必须单独设计身份认证、授权、传输加密、凭据安全存储与数据留存策略，不能复用本地文件权限模型。

## 6. 交互与 UI

UI 设计已产出**可交互原型**：`docs/UI设计原型.html`（浏览器直接打开），包含：

1. 桌面端采用与 TextAnalysisTool 一致的上下双窗格：文件会话与命令栏、最大化原始日志阅读区、底部规则/详情工作台、状态栏；
2. 底部规则工作台明确展示“包含 → 排除 → 当前视图”的处理管道，规则持续可见且可开关、新增、删除、导入、导出；
3. 三种显示模式、查找高亮与跳转、双击按 Tag 建规则、将当前查找一键保存为规则均可真实操作；
4. 选中桌面日志行自动进入详情，展示时间、级别、Tag、PID/TID 和原始内容；可一键关联当前 Tag、复制定位；
5. 移动端适配布局（过滤器收入底部抽屉、底部导航、搜索与简化行操作），以及深色 / 浅色主题和完整设计规范。

> 原型用于验证信息架构和交互优先级，不代表远程数据源已纳入 MVP；日志解析、JSON 与脱敏以第 3.10、3.11 节的阶段定义为准。

## 8. 决策记录与遗留问题

### 8.1 已确认决策（2026-09-02）

| # | 决策项 | 结论 |
|---|---|---|
| D1 | MVP 顺序 | **桌面端先行**（第一批 MVP 仅桌面），移动端第三批交付 |
| D2 | 超大文件（5GB+） | **纳入支持目标**（允许合理降级，核心功能必须可用，见 4.1） |
| D3 | 界面语言 | **仅中文**，不做国际化 |
| D4 | 插件系统 | **不做**，已从需求中移除 |
| D5 | UI 方向 | 采用 TextAnalysisTool 的经典上下双窗格结构：命令栏 + 原始日志区 + 底部规则/详情工作台 + 状态栏；以现代化主题、会话与解析信息提升效率，以 `docs/UI设计原型.html` v4 为基准 |
| D6 | 结构化策略 | 原始文本为唯一可信底座；日志字段、JSON 与关联能力均为可回退的渐进增强，不得改变原始内容和行号 |
| D7 | Include 空集语义 | **无启用 Include 时展示全部行**；Exclude 仍可单独用于屏蔽噪声行 |
| D8 | 堆栈逻辑块 | **不做**；无法稳定判断连续文本是否属于同一异常堆栈，始终按原始行呈现 |
| D9 | 实时 Tail | **P2 增强**；以分析已落盘日志为主，后续再支持增量追加与跟随 |
| D10 | Web 端 | **保留为 P2 增强**；第四批实施前评估浏览器文件访问与大文件性能方案 |
